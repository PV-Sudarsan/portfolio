Module 01

Core Concepts

The building blocks you must understand before writing a single command.

📦

Container

A lightweight, isolated environment that packages your app with all its dependencies. Containers share the host OS kernel but run in isolation — faster than VMs, more consistent than bare metal.

docker run
🖼️

Image

A read-only template used to create containers. Images are built in layers — each instruction in a Dockerfile adds a new layer. Layers are cached and reused for fast builds.

docker build
📋

Dockerfile

A text file with instructions to build an image. FROM sets the base, RUN executes commands, COPY adds files, and CMD defines the default process that runs inside the container.

docker build -t
🗄️

Volume

Persistent storage that survives container restarts and deletions. Data written to volumes is stored on the host filesystem and can be shared between multiple containers.

docker volume
🌐

Network

Virtual networks that allow containers to communicate. Bridge networks are default for single-host. Overlay networks span multiple Docker hosts in a swarm cluster.

docker network
🏗️

Docker Compose

A tool for defining and running multi-container apps using a YAML file. Define services, networks, and volumes in one place — spin up your entire stack with one command.

docker compose up
