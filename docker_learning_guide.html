Example with Nginx

docker pull nginx
docker run -d --name my-nginx -p 8080:80 nginx
docker ps

docker stop my-nginx
docker rm my-nginx

Build Images

Dockerfile Basic Example

Create a file named Dockerfile.

FROM nginx:latest
COPY . /usr/share/nginx/html
EXPOSE 80

Build Image

docker build -t my-website .

Run Container

docker run -d --name website -p 8080:80 my-website
Multi Container

Docker Compose Basic Example

Create a file named docker-compose.yml.

services:
  web:
    image: nginx
    container_name: nginx-web
    ports:
      - "8080:80"

Run

docker compose up -d

Stop

docker compose down

View Logs

docker compose logs -f
Important

Very Important Docker Cautions

1. Be Careful with Delete Commands

These commands remove all containers or images. Use only when you are sure.

This removes all containers:

docker rm -f $(docker ps -aq)

This removes all images:

docker rmi -f $(docker images -aq)

2. Do Not Store Passwords Inside Dockerfile

Avoid this:

ENV DB_PASSWORD=mysecretpassword

Better use environment variables:

docker run -e DB_PASSWORD="yourpassword" app-image
For production, use AWS Secrets Manager, Azure Key Vault, Docker Secrets, or another secure secret management service.

3. Do Not Run Containers as Root in Production

RUN adduser appuser
USER appuser

4. Always Use Specific Image Versions

Avoid:

FROM node:latest

Better:

FROM node:20-alpine
The latest tag can change anytime and may break your application.

5. Be Careful with Ports

docker run -p 8080:80 nginx
Part Meaning
8080 Host machine port
80 Container port
Do not expose database ports publicly unless required.

6. Use Volumes for Important Data

Without a volume, data may be lost when the container is removed.

docker volume create mysql_data
docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=root123 \
  -v mysql_data:/var/lib/mysql \
  mysql:8

7. Clean Unused Docker Data Safely

Safe cleanup:

docker system prune

More aggressive cleanup:

docker system prune -a
Be very careful: docker system prune -a removes unused images also.
Roadmap

Best Learning Order

  1. Docker basics: image, container, volume, and network
  2. Run simple containers like Nginx, Ubuntu, and MySQL
  3. Learn Dockerfile
  4. Learn Docker Compose
  5. Learn volumes and networking
  6. Learn logs, debugging, and troubleshooting
  7. Learn Docker security best practices
  8. Learn deployment with AWS ECS, EKS, or Kubernetes
